# Trackpad DJ

맥북 내장 트랙패드 전체를 하나의 세로 조그휠로 사용하고, 키보드로 활성 덱을 전환하며 2덱 믹싱을 수행하는 macOS 실험 앱입니다. 프로 DJ 하드웨어를 복제하기보다 로드, 트랜스포트, 기본 스크래치, 피치 벤드, 템포, 필터, 볼륨, 크로스페이드와 프리큐가 한 흐름으로 동작하는 데 집중합니다.

## 요구 사항

- macOS 13 이상
- Swift 5.9 이상
- 멀티터치 간접 입력을 제공하는 맥북 내장 트랙패드
- Split Cue 청취 시 좌우 채널을 분리해 들을 수 있는 스테레오 헤드폰 또는 출력 장치

오디오 엔진은 AVFoundation과 Accelerate를 사용합니다. 동시성 경계에는 `swift-atomics` 1.2.0을 고정해 사용하며, 별도 오디오 런타임은 필요하지 않습니다.

## 빠른 시작

시스템 출력 볼륨을 낮춘 상태에서 서로 다른 오디오 파일 두 개를 준비합니다. 저장소 루트에서 다음 명령을 실행합니다.

```bash
swift build
.build/debug/TrackpadDJ
```

앱을 종료할 때는 `Command+Q`를 사용합니다. 터미널에서 직접 실행한 프로세스가 남아 있다면 `Control+C`로 종료할 수 있습니다.

## 5분 실기기 테스트

아래 순서를 그대로 따라가면 로드부터 두 덱 전환까지 핵심 기능을 빠르게 확인할 수 있습니다.

| 순서 | 직접 해볼 동작 | 정상 결과 |
|---|---|---|
| 1. 시작 상태 | 앱을 실행합니다. | Deck A가 파란색으로 활성화되고 상단에 `JOG A / SCRATCH`, 중앙에 `A+B ON`이 표시됩니다. |
| 2. 두 곡 로드 | `Q`로 첫 곡을 Deck A에 고른 뒤, `Tab` → `Q`로 두 번째 곡을 Deck B에 고릅니다. | 각 덱에 트랙명과 파형이 나타납니다. 분석에 성공한 곡은 BPM과 비트 그리드도 표시됩니다. |
| 3. 재생과 큐 | `Space`로 활성 덱을 재생·정지하고 `C`로 큐 위치에 돌려놓습니다. `Tab`으로 덱을 바꿔 반복합니다. | 선택한 덱만 반응하고 반대 덱의 재생 상태와 위치는 바뀌지 않습니다. |
| 4. 스크래치 | 곡을 재생한 뒤 화면 버튼이 없는 곳에서 두 손가락을 올려 트랙패드를 세로로 움직입니다. 이어서 수평으로만 움직여 봅니다. | 세로 입력은 활성 덱만 앞뒤로 움직이고 `SCRATCH` 값이 표시됩니다. 수평 입력은 볼륨·필터·크로스페이더를 바꾸지 않습니다. 손을 떼면 설정 템포로 복귀합니다. |
| 5. 피치 벤드 | `Shift`를 먼저 누른 채 두 손가락을 올리고 세로로 움직인 뒤 손을 뗍니다. | 모드가 `BEND`로 고정되고 활성 덱만 최대 ±8%까지 순간 변속합니다. 손을 떼면 벤드가 0%로 돌아옵니다. |
| 6. 덱 파라미터 | `E/D`로 볼륨, `R/F`로 필터, `T/G`로 템포를 조절하고 `5`로 템포를 초기화합니다. | 활성 덱의 해당 다이얼만 변하고 값은 허용 범위를 넘지 않습니다. |
| 7. 크로스페이더 게이트 | 기본 중앙에서 `←`를 누르면 `A ON`, `→`를 누르면 `A+B ON`, 한 번 더 `→`를 누르면 `B ON`이 됩니다. | ON인 덱의 채널 볼륨은 그대로이고 OFF인 덱만 무음이 됩니다. 크로스페이더 이동에 따라 ON인 덱의 볼륨이 커지거나 작아지지 않습니다. |
| 8. BPM과 SYNC | 두 덱에 BPM이 표시되면 `S`를 누릅니다. 비트에 맞춰 `B`를 여러 번 탭한 뒤 `Shift+B`도 눌러 봅니다. | 필요한 템포가 ±8% 이내면 `S`가 활성 덱의 템포만 한 번 조정합니다. 범위를 넘으면 실패 문구가 나오고 값이 유지됩니다. `B`는 탭 BPM으로 바뀌고 `Shift+B`는 자동 분석값으로 복원합니다. 위상과 재생 위치는 자동으로 이동하지 않습니다. |
| 9. 커서 잠금 | 앱이 활성 창이고 커서가 콘텐츠 안에 있을 때 `P`를 누른 뒤 `Esc`를 누릅니다. | `CURSOR LOCKED`가 표시되며 커서가 숨겨지고, `Esc`에서 조그가 취소되면서 커서가 즉시 복구됩니다. |

가장 중요한 성공 기준은 다음 네 가지입니다.

- 한 덱을 조작할 때 반대 덱의 값이 바뀌지 않는다.
- 스크래치와 피치 벤드가 터치 종료 후 남지 않는다.
- 크로스페이더가 ON인 덱의 채널 볼륨을 바꾸지 않는다.
- `Esc`, 파일 선택, 포커스 상실과 앱 종료 후 커서가 정상 복구된다.

`A+B ON`에서는 각 덱을 증폭하거나 감쇠하지 않지만 두 곡의 신호가 합산되므로 전체 Master가 더 크게 들릴 수 있습니다. 이는 크로스페이더가 개별 덱의 볼륨을 올린 결과가 아닙니다.

### 헤드폰 Split Cue 테스트

이 테스트는 좌우 채널을 구분해서 들을 수 있는 스테레오 헤드폰에서만 수행합니다. 청력과 장비를 보호하도록 시스템 볼륨을 먼저 낮춥니다.

1. 두 덱을 재생하고 `M`을 눌러 `SPLIT CUE / L: MASTER / R: CUE` 표시를 확인합니다.
2. `Tab`으로 미리 들을 덱을 활성화한 뒤 `V`로 `MON`을 켭니다.
3. 왼쪽에서는 Master만, 오른쪽에서는 선택한 덱의 프리큐만 들리는지 확인합니다.
4. `V`를 다시 눌러도 왼쪽 Master 음량이 변하지 않는지 확인합니다.
5. `M`을 눌러 `STEREO MASTER`로 돌아옵니다.

## 자동 테스트

소스 수준 회귀 검사는 다음 명령을 순서대로 실행합니다.

```bash
swift build
swift test
Scripts/verify-strict-concurrency.sh
git diff --check
```

현재 기준으로 `swift test`는 67개 테스트가 모두 통과해야 합니다. 엄격 동시성 스크립트는 `-strict-concurrency=complete -warnings-as-errors`로 별도 빌드하며, `git diff --check`는 성공 시 아무 내용도 출력하지 않습니다.

자동 테스트는 실제 트랙패드 감각, 다양한 장르의 BPM 정확도, 헤드폰 채널 청취, 레이턴시, 클릭 노이즈나 30분 연속 믹싱을 증명하지 않습니다. 실기기 결과는 [Docs/Verification.md](Docs/Verification.md)의 체크리스트에 기록합니다.

## 퍼포먼스 콘솔

기본 창은 1180×720이고 960×620까지 줄일 수 있습니다. 위쪽에는 Deck A/B 스크롤 파형을 세로로 쌓고, 아래쪽에는 덱별 파라미터와 프리페이더 미터, 중앙 단일 플래터와 3단 크로스페이더 게이트를 배치합니다. 활성 덱은 파형·덱 헤더·플래터 색으로 함께 강조합니다.

`LOAD`, `CUE`, `PLAY/PAUSE`, `SYNC`, `MON`, Deck A/B 선택과 `STEREO MASTER / SPLIT CUE`는 화면에서 클릭할 수 있습니다. 비활성 덱의 버튼을 누르면 해당 덱을 먼저 활성화한 뒤 명령을 실행합니다. 볼륨·필터·템포와 크로스페이더는 현재 값을 시각화하지만 연속 마우스 조작은 제공하지 않으며 기존 키보드 계약을 사용합니다.

커서 잠금이 꺼진 상태에서 포인터가 클릭 가능한 컨트롤 위에 있을 때 시작한 첫 터치는 그 터치 시퀀스 전체를 버튼 클릭에 예약해 조그를 발동하지 않습니다. 버튼 밖에서 시작하거나 커서 잠금이 켜진 상태에서는 전체 표면 조그가 그대로 우선합니다.

## 컨트롤

### 트랙패드 조그

- 한 손가락: 조그 없음, 재생 유지
- 두 손가락 세로 드래그: 활성 덱 스크래치
- `Shift`를 누른 상태에서 두 번째 손가락을 올린 뒤 세로 드래그: 활성 덱 ±8% 피치 벤드
- 수평 이동: 무시
- 시작한 두 손가락의 속도를 항상 2로 나눠 평균: 한쪽만 움직이면 두 손가락을 함께 움직일 때의 절반 감도
- 세 번째 이후 터치: 화면 시각화만 수행
- 한 손가락만 남거나 시작한 두 손가락 중 하나를 떼면 조그 해제
- 조그 후 한 손가락만 남으면 커서 잠금도 해제되어, 남은 손가락으로 커서를 옮기고 화면 버튼을 클릭할 수 있음. 다시 잠그려면 `P` 사용
- 커서 잠금 해제 상태의 버튼 위 첫 터치: 해당 시퀀스는 UI 클릭 전용

스크래치 속도는 두 손가락 평균 `velocityY × 3.3`을 `-8...8`로 제한합니다. 피치 벤드는 평균 `velocityY × 8`을 `-8%...+8%`로 제한하며 설정 템포와 합산됩니다. 정지 프레임에는 즉시 목표값을 0으로 만들고, 이벤트가 끊기면 마지막 이동 후 20ms 이상 지난 첫 타이머 틱에서 0으로 만듭니다. 종료·취소 시 설정 템포 재생으로 복귀하며 피치 벤드는 정지한 덱을 이동시키지 않습니다.

스크래치 반응은 샘플 단위 2ms 시정수로 부드럽게 연결합니다. 정지 부근에는 1ms 시정수의 출력 페이드를 적용하고, 고속 스크래치에는 앨리어싱을 줄이는 필터를 적용합니다. 테스트할 때는 같은 보컬 구간에서 두 손가락을 함께 짧게 왕복하고, 중간 정지·손 떼기·빠른 왕복의 소리를 비교해 주세요. 실제 청취 품질은 아직 미검증입니다.

두 번째 손가락을 올려 조그가 시작되는 시점에 덱과 모드가 고정됩니다. 한 손가락만 남았다가 다시 두 번째 손가락을 올리면 새 조그를 시작합니다. 터치 도중 `Tab`이나 `Shift` 상태가 바뀌어도 현재 조그는 기존 덱과 모드로 끝나며 다음 터치부터 새 상태가 적용됩니다.

빠른 UI 전환 테스트: 두 손가락으로 스크래치 → 한 손가락만 떼기 → 남은 손가락으로 `MON`이나 `PLAY` 버튼까지 이동해 클릭합니다. 볼륨·필터·템포 다이얼과 크로스페이더는 여전히 표시 전용이며 키보드로 조절합니다.

### 키보드

| 키 | 기능 |
|---|---|
| `Tab` | 활성 덱 A/B 전환 |
| `Q` | 활성 덱 오디오 파일 선택 |
| `Space` | 활성 덱 재생·정지 |
| `C` | 활성 덱 큐, 2초 프리롤 시작점으로 복귀 |
| `S` | 활성 덱을 반대 덱의 현재 유효 BPM에 원샷 매치 |
| `E` / `D` | 활성 덱 볼륨 증가 / 감소 |
| `R` / `F` | 활성 덱 필터 열기 / 닫기 |
| `T` / `G` | 활성 덱 템포 증가 / 감소 |
| `5` | 활성 덱 템포 0% 초기화 |
| `B` | 활성 덱 탭 BPM 보정 |
| `Shift+B` | 탭 보정 제거 후 자동 BPM 복원 |
| `V` | 활성 덱 프리큐 선택 토글 |
| `↑` / `↓` | 활성 덱 앞 / 뒤로 너지 |
| `←` / `→` | 전역 크로스페이더 `A ON → A+B ON → B ON` 전환 |
| `M` | Stereo Master / Split Cue 전환 |
| `P` | 커서 잠금·숨김 토글 |
| `Esc` | 활성 조그 취소와 커서 잠금 해제 |

볼륨·필터·템포·너지 키는 누른 시점의 덱에 고정됩니다. 키를 누른 채 `Tab`을 눌러도 다른 덱으로 넘어가지 않습니다. 템포는 키를 누르는 동안 약 60fps로 0.05%씩 바뀝니다. Command, Control 또는 Option 조합은 앱이 가로채지 않고 macOS로 전달합니다.

조그는 `P` 상태와 무관하게 항상 동작합니다. `P`를 켜면 앱이 키 윈도우이고 커서가 콘텐츠 안에 있을 때만 커서 이동 결합을 끊고 숨깁니다. `P`, `Esc`, 파일 선택, 포커스 상실, 창 닫기와 앱 종료 시 복구합니다.

## BPM과 원샷 SYNC

트랙을 로드하면 백그라운드 작업에서 최대 첫 90초를 200Hz 모노 에너지 엔벌로프로 만듭니다. 짧은 삼각 평활화로 프레임 단위 에너지 흔들림을 줄인 뒤 onset autocorrelation을 계산하고, 80~160 BPM 기본 후보와 가능한 2배 템포 증거를 함께 평가해 첫 박자를 찾습니다. 8초 미만이거나 선택한 기본 후보의 신뢰도가 0.35 미만인 신호는 분석 실패로 남깁니다.

자동 분석을 빠르게 확인하려면 곡을 로드한 뒤 BPM 아래에 `AUTO`가 표시되는지 봅니다. 알고 있는 BPM과 약 1~2 BPM 이내인지 비교하고, 결과가 없거나 크게 다르면 4박 이상 `B`를 탭해 수동값과 비교합니다. 자동값은 80~160 범위이므로 약 190 BPM으로 더블타임 탭한 곡이 자동으로 약 95 BPM에 표시되는 것은 같은 템포 계열입니다. `Shift+B`를 누르면 자동값으로 돌아갑니다.

`B` 탭은 2초 이상 간격에서 새 시퀀스를 시작하고 최근 8회 간격을 평균합니다. 두 번째 탭부터 자동 분석값을 덮어쓰며 첫 탭 당시 재생 위치를 첫 박자로 사용합니다. `Shift+B`로 원래 자동 분석값을 복원할 수 있습니다.

`S`는 반대 덱의 수동 템포까지 반영한 유효 BPM을 목표로 활성 덱 템포를 한 번 설정합니다. 필요한 템포가 ±8%를 넘거나 어느 한 덱의 BPM이 없으면 아무 값도 바꾸지 않습니다. 위상과 재생 위치를 맞추거나 이후 지속적으로 동기화하지는 않습니다.

## Split Cue

기본 출력은 `Stereo Master`입니다. `M`으로 Split Cue를 켜면 다음과 같이 출력합니다.

- 왼쪽: 포스트 페이더·포스트 크로스페이더 마스터의 모노 합산
- 오른쪽: `V`로 선택한 포스트 EQ·프리 페이더 활성 덱의 모노 프리큐
- 두 덱을 동시에 모니터하면 각 프리큐를 0.5 게인으로 합산

Split Cue 중에는 `L: MASTER / R: CUE` 경고를 계속 표시합니다. 출력 장치 재구성에 실패하면 엔진을 중단하고 오류를 표시하며, 프리큐를 마스터로 자동 유출하지 않습니다.

## 오디오와 입력 구조

```text
원시 터치/키보드 → GestureStateMachine / KeyboardStateMachine → DJAction
                                                               ↓
TrackLoader + BeatGridAnalyzer → LoadedTrack → Deck → AudioEngine
                                                   ↓
                                      DeckSnapshot / MixerSnapshot → UI
```

각 덱의 기본 오디오 경로는 다음과 같습니다.

```text
AVAudioSourceNode → low-pass EQ → master/cue path → output routing → main mixer
```

- 파일은 전체 `AVAudioPCMBuffer`로 로드하지만 디코딩, 파형과 BPM 분석은 백그라운드에서 수행합니다.
- 재생 위치는 렌더러만 변경하고 UI 명령은 `DeckRealtimeState`의 atomic 값과 세대 번호로 전달합니다.
- 렌더러가 덱별 실제 출력 샘플의 최대 절댓값을 atomic 피크로 발행하고 UI가 이를 소비해 프리페이더 미터를 표시합니다.
- 일반 재생률은 `1 + (tempoPercent + pitchBendPercent) / 100`입니다.
- 스크래치 중에는 스크래치 속도가 템포와 피치 벤드를 대체합니다.
- 일반 샘플 읽기는 4-point Cubic Hermite 보간을 사용하고, 1배속 초과 스크래치는 사전 계산한 32-tap windowed-sinc 필터로 점진적으로 전환합니다.
- 크로스페이더는 `A ON → A+B ON → B ON`의 3단 출력 게이트입니다. 켜진 덱은 채널 페이더 게인을 그대로 유지하고 선택되지 않은 덱만 뮤트합니다.

## 남은 검증과 후속 범위

가장 먼저 맥북에서 버튼 위 터치가 조그를 억제하고 버튼 밖 터치는 조그로 이어지는지, 전체 트랙패드 조그와 `Shift` 피치 벤드, 커서 잠금 복구가 의도대로 동작하는지 확인해야 합니다. 이어서 창 크기 변경, 실제 음악 BPM 정확도, 두 트랙 전환, Split Cue 청취, 출력 장치 연결·해제와 30분 연속 사용을 검증합니다.

핫큐, 루프, 자체 트랙 브라우저, 키락, 자동 위상 정렬과 지속 Sync는 현재 범위가 아닙니다. 자세한 상태는 [Docs/Verification.md](Docs/Verification.md)를 참고하세요.
